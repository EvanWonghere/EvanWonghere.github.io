# 英语朗读室

入口 `/study/english/`，Hugo 页面在 `layouts/english/single.html`。前端无构建步骤。

## 文库与阅读

- 首页是“今日一篇”加文库：35 篇，包括 30 篇公有领域名篇（诗歌 12、散文 6、演讲 5、小说 5、书信 2）和 5 个原创情景课。`#free` 是原来的自由练习，`#w/<id>` 打开一篇，`#w/<id>/follow` 是逐句跟读。
- `library/*.json` 是**生成物**，不要手改。来源是 `tools/english-library/specs/<id>.json`（事实与我们自己写的导读、提示、释义）加上下载的原文，用 `tools/import-english-text.mjs` 生成，用法见 `tools/english-library/README.md`。原文由工具从 Wikisource 或 Project Gutenberg 切出，不手打。
- 版权规则：必须同时满足美国公有领域（1930 年及以前出版，或美国政府作品）和中国公有领域（作者及译者去世满 50 年）。不满足时 `build` 失败。导读等为原创，需要你审阅事实。
- 作品和句子的 id 发布后不变。每段不超过 40 词（按每分钟 100–120 词约 20–24 秒；录音上限 25 秒，评分上限 30 秒），因为带评分的单次请求最多 30 秒。
- “今日一篇”只由日期决定：周日演讲，周一、周四、周六诗歌，周二散文，周三小说，周五书信，用完一轮才会重复；不依赖读过什么，所以同一天打开总是同一篇。
- 逐句跟读时，诗歌默认按“句子或分句”成组（以 . ; : ! ? 结尾，或四行后遇逗号，或快到 40 词时切开），不会把跨行的句子拆开；可勾选“逐行拆开”。提交给评分的文本把换行合并成空格。
- 范读用浏览器自带的朗读（`speak.mjs`）。本机系统语音有逐词位置，高亮才准；部分网络语音没有，此时页面提示没有高亮。预生成的范读音频还没有做。
- 阅读页没有任何数据写入：不存进度，不上传。评分和历史仍只在跟读/自由练习的练习区。

## 朗读整篇、实时亮词与报告

- `#w/<id>/read`（“朗读整篇”）：一段一段读。每段用练习区的录音按钮录，读完停在这一段的小结（可重读），读完所有段后进入总结：管理员勾选要送评的段落，访客只看本地比对。报告含正确词/分钟、读对率、各项评分、需要练的词（附音素提示）和最弱的音。“练这个词”把练习区切到单个词。
- **实时亮词（实验，默认关）**：练习区的开关。开启后，录音时浏览器自己的听写（SpeechRecognition）边听边把读到的词亮起，漏读或读成别的词标红；读完得到“读对 x / y 词”和每分钟词数。Chrome 把声音交给 Google，Safari 交给 Apple，**本站不接收**；也不影响评分。听写本身会出错（缩写、连读、数字），所以这只是提示，不是成绩。开关记在 localStorage `hive-english-prefs-v1`，只存这一个布尔值。
- 本地比对用词级最长公共子序列（`align.mjs`），思路借鉴 dasheng，但没有复制它的代码（它没有显示开源许可）。
- 页面底部的“实时听写测试”仍在：只检查这个浏览器能不能听写，只有点“开始测试”才启动，不保存任何东西。
- 朗读整篇的评分结果同样按段写入历史（`hive-english-v1`，最多 50 条），所以一篇会占几条。

## 背诵、配音与学习档案

- **背诵**（`#w/<id>/recite`，真实作品才有，情景课没有）：一段一段凭记忆背，用练习区录音。三级提示：1 级每行只留前半截，2 级每个词只留首字母，3 级每行只给第一个词的首字母；背诵时练习区里的原文会被隐藏。有实时听写时按 Poetry Out Loud 的算法给准确度 8 分：错或漏一个词扣 1 分，整行漏掉扣 3 分，6 分及以上算这一段通过；没有听写时对照原文自评。整篇所有段都通过，才记这一级“已背下”。听写会出错，所以分数只作参考。
- **配音**（`#w/<id>/dub`，只有对话课有）：选一个角色，另一个角色由设备的范读自动读出（两个角色音高略不同）；轮到你的句子才录音，总结里只列你读的句子。对话课的数据是 `roles` 加每句的 `speaker`。
- **学习档案**（`#archive`，页面右上“档案”）：每天练习的时长、读过和背下的作品、生词本、得分低的音。存在 localStorage `hive-english-progress-v1`，**不含任何录音**，也不上传；可以导出和导入（导入是合并，原有内容都保留，数字取较大值）。存储被禁用，或档案损坏、来自更新的版本时，页面不写入，原数据原样保留。
  - 一次录音完成就算当天练了；读完一篇（朗读整篇或配音走到总结）记“读过”；报告里的发音分记作“最好成绩”。
  - **生词本**：在“听”模式里点词，选“＋ 生词本”；朗读报告里的难词可一键加入。作品里出现生词本的词时，会加一个小圆点。
  - **复习**：新词明天到期，之后间隔 1、3、7、14、30 天。复习时先读，再看释义和原文例句，选“想起来了”就往后推一步，选“还不熟”明天再来。管理员评分时，到期的词得分 ≥ 85 自动往后推一步，< 70 退回明天。
  - **最弱的音**：美式评分里每个音最近 3 次的平均分，低于 70 的列出来，附音素提示。

## 范读的三种声音

1. **设备自带**（默认）：浏览器的语音合成，逐词高亮；声音因设备而异。
2. **真人朗读**（`library/` 里作品的 `human` 字段，文件在 `human/`）：13 篇（12 首诗加葛底斯堡演说）有 LibriVox 志愿者的录音，听模式里有独立的播放器，署名和来源（`human/NOTICE.md`）显示在播放器下。录音是公有领域，共约 9 MB；用的版本可能和页面文字略有出入，所以只作为可选的一条音轨，不做逐词高亮，也不参与评分。
3. **预生成的神经网络声音**（`voice/`）：用 `tools/render-english-voices.mjs` 生成。**2026-10-09 已生成美式（Jenny、Guy）38 篇，共 15 MB；英式（Sonia、Ryan）还没有生成**，英式口音下仍用设备声音，要的话运行 `--accents en-GB`（约 15 MB、一小时左右）。有预生成音频时，听、跟读、朗读整篇、背诵、配音里的范读都会自动用它，听模式里多一个“声音”选项可以改回设备自带。
   - 运行：先 `node tools/render-english-voices.mjs --init-key` 创建 `~/.config/hive-english/azure.env`（在用户目录里，不在仓库内；工具会拒绝仓库内或别人可读的密钥文件），把密钥填进去；再 `--check` 验证，`--dry-run` 看规模，最后 `--accents en-US`。密钥也可以用环境变量 `AZURE_SPEECH_KEY`。密钥不会被打印或写到别处。可中断后续跑，只重新生成文本变过的作品；`tests/english-voice.test.mjs` 会在文字改了而音频没重新生成时报错。
   - 规模：38 篇 343 句、3.5 万字符，美式 15 MB（`--format audio-16khz-32kbitrate-mono-mp3` 约 10 MB）。免费档限速约每分钟 20 次请求，默认每次请求间隔 3.2 秒，实测美式用了约 50 分钟。字符数远在每月免费额度内。
   - 每句（诗的一个分句）单独合成再拼接，所以“哪一句从几秒到几秒”是精确的。时间轴版本 2 还给每个词记了起止时间：工具用 Speech SDK 合成，Azure 在合成时报告每个词的起点，所以听模式的高亮是逐词走的，不是估算。Azure 偶尔把两个词合成一个事件（如“in 1864”），工具按字母数在两个词之间分摊；某个词完全没有时间时工具直接报错，不会写入猜测。`wordAt`（`voice.mjs`）按当前播放时间找词，停顿时保持上一个词亮着。版本 1（只有句时间）仍然有效，高亮整句。生成的时间轴带文本指纹，作品文字改了，旧音频就不会再被使用。
   - SDK 只是这个工具的依赖，不在仓库里：`mkdir -p ~/.cache/hive-english/sdk && cd ~/.cache/hive-english/sdk && echo '{"private":true}' > package.json && npm install microsoft-cognitiveservices-speech-sdk@1.52.0`（`--sdk <文件夹>` 或环境变量 `HIVE_SPEECH_SDK` 可指向别处；`--rest` 退回普通 HTTPS，只有句时间）。SSML 里的引号不转义成 `&quot;`：Azure 对它报告的词位置是错的（-1）。
   - 这是新增 20–40 MB 的二进制文件，会进入仓库历史；动手前先决定生成几种口音和哪种码率。

## 目标口音（美式 / 英式）

- 页面右上的“目标口音”（和练习区的“口音”是同一个设置，互相同步，并记在 `hive-english-prefs-v1`）决定四件事：范读和读词用哪种英语语音、实时亮词让浏览器按哪种口音听写、评分按哪种口音打分、历史里记的口音。切换后，已录好的录音要重录才能按新口音评分。
- 英式口音**可以评分**，得到综合、准确度、流利度、完整度和逐词、音素分数；**没有**韵律分和语调、停顿提示（微软文档里这些只支持美式）。音素提示表是按美式英语写的，英式口音下不显示，避免误导（比如英式的词尾 r 通常不卷舌）。
- 范读用设备自带的语音：设备里没有英式语音时，会退回另一种英语语音，并在页面上说明用的是哪种。macOS 通常自带 Daniel（en-GB）。
- 未验证：英式口音的真实评分返回里音素名、词的起止时间是否和美式一样。上线前请用管理员账号评一次英式。

## 评分的增强部分

- **详细评分：“你读成了什么音”**（管理员，美式，练习区的开关，默认关）：REST 接口会忽略 `PhonemeAlphabet`/`NBestPhonemeCount`（2026-10-09 实测：音素名仍是 SAPI，没有候选），所以这一项走 Azure Speech SDK 的 WebSocket 通道，**在 `speech-assess` 函数里（服务器端）进行**，浏览器仍然只用 HTTPS。结果多出：每个音素的 IPA 名、“最像是读成了哪个音”（候选读音），页面写成“你读成了 /v/”。通道不可用（SDK 在边缘函数里加载失败、连接超时等）时函数自动改用 REST，返回里带 `HiveDetail: 'unavailable'`，页面会说明。
  - 之前以为 WebSocket 在站长的网络上不通，那只说明**浏览器直连 Azure** 不通；服务器端连没有这个问题，本机用同一个 SDK 版本（1.52.0）实测可用，在 Deno 里也可用。
  - SDK 的代码在 `supabase/functions/speech-assess/sdk.ts`，只在请求详细评分时才动态加载，加载失败不影响普通评分。SDK 的报错信息可能带连接地址（里面有密钥），所以只向外报一个词。

- 美式口音（en-US）请求韵律评分（`EnableProsodyAssessment`），结果多一项“韵律”，并标出整段语调偏平、词前的不自然停顿。英式口音没有这些，文档里韵律只支持 en-US。
- 每个词保留起止时间，所以单句练习里可以“听我读的这个词”（用评分时发送的那份 16 kHz WAV 切出）。
- 音素提示（`phoneme-tips.mjs`）按 REST 默认的 SAPI 音素名（th、v、ih……）写成中文，是我们自己的话，需要老师过目。
- 韵律评分已在线上验证：美式评分的结果里有“韵律”分（2026-10-09 管理员实测），请求写法按文档用字符串 `"True"`。仍待确认：返回里词的起止时间（单句练习里“听我读的这个词”靠它）和 `UnexpectedBreak` 的置信度阈值 0.75 是否合适。后端只改了一行（`supabase/functions/speech-assess/core.mjs`，按口音决定是否请求韵律）；部署版本 2026-10-09 起为第 2 版，回滚用提交 `9e841440` 里的 `core.mjs`。

## 行为与隐私

- 录音使用浏览器 MediaRecorder，最多 25 秒。音频先在页面内存中保存，可回听或丢弃，刷新即失。
- 点击评分时才把音频、参考文本发送到已有 Azure Speech 资源 `hive-english-speech-20261009`（`southeastasia`，F0）。音频本地解码、降混为单声道、重采样为 16kHz、编码 PCM16 WAV 后通过 HTTPS 发送到 `speech-assess`，后端立即转发到 Azure 短音频 REST 评分接口，不写入数据库/存储、不记录音频日志。
- 短句最多 60 词 / 600 字符；录音后的文本或口音变更必须重录。使用单次短音频发音评估，音素粒度、误读检查开启、韵律附加评估关闭。长停顿可能结束首个语段，页面提示核对完整度和漏读。
- 成绩来自 Azure，显示综合、准确度、流利度、完整度及单词/音素分数。缺少的分数显示 `—`；不会假造分数，也不把它作为水平认证。
- 历史仅写 `hive-english-v1`，最多 50 次。另有 `hive-english-prefs-v1` 只存“实时亮词”开关，不含成绩。无录音数据、无云端成绩表，不读写音乐/题库成绩。读取、写入、导入均校验 v1；损坏或较新版本保留原值，阻止覆盖。导入合并 ID、保留已有冲突项，保留最近 50 次。
- 评分须通过现有 Supabase 管理员身份。访客可录音/回听，不能调用评分接口。通过题库登录再返回，复用已有 session，无新增 OAuth 回调地址或 Auth 配置变更。
- 管理员可点击“测试完整评分（公开示例）”，用微软公开的 2.03 秒 WAV 验证授权、浏览器连接、音频上传及实际评分；不会发送自己的录音、不写入练习历史，示例请求也会计入 Azure 用量。前端不加载 Speech SDK、不直接连接 Azure WebSocket；Azure 密钥和 token 不返回浏览器。

## 后端与部署

本功能独立的 `speech-assess` 函数源码在本仓库 `supabase/functions/speech-assess/`。旧版 `speech-token` 和 SDK 适配器仅保留作回滚参考，当前页面不调用它们。它与题库共用现有 Supabase 项目 `vtbwqnigocrbpmbkbiiv` 的 Auth 和 `is_app_admin()`；不修改 `ai-tutor`、表、RLS、音乐成员权限或题库构建。

部署需先确认，只部署这一函数：

```sh
supabase functions deploy speech-assess --project-ref vtbwqnigocrbpmbkbiiv --no-verify-jwt --use-api
```

在该项目 Edge Function Secrets 中设置 `AZURE_SPEECH_KEY`（Azure 资源“密钥和终结点”的密钥）、`AZURE_SPEECH_REGION=southeastasia`。密钥只保存在服务端 Secret，不能放 Hugo 配置、源码、命令参数或日志。无需数据库迁移，不能运行 `db push` 或改变已有函数的秘密。

`verify_jwt=false` 是为了支持 publishable key；函数内部必须先用 `auth.getUser(token)` 验证 JWT，再以该用户身份调用 `is_app_admin()`，失败即拒绝。每次请求重新检查权限。CORS 仅允许主站和本机 1313 端口；它是浏览器限制，真正权限来自身份校验。评分请求体流式限制为 1.12 MB，参考文本限制 60 词 / 600 字符，口音仅 en-US/en-GB；服务端验证 WAV 为 PCM16、单声道、16kHz，并限制实际音频时长（最多 26 秒编码余量）。Azure HTTPS 请求超时 45 秒；浏览器总超时 60 秒。不自动重试，避免重复计费。

F0 资源保持原套餐，不自动升级；实际额度和停用状态以 Azure 控制台为准。取消评分/网络超时不保证 Azure 未处理请求；重试可能重复计入用量。

## 检查

`node --test tests/*.test.mjs` 覆盖 WAV 编码、成绩解析/记录校验、未登录/普通用户门禁、权限撤销/缓存、CORS 和 Azure 故障。`hugo --minify` 构建页面。完整 HTTPS 评分链路及麦克风需要真实浏览器验证：

1. 访客录音、回听、丢弃；确认麦克风在结束、切后台、离开页面后释放；刷新录音消失。
2. 管理员通过题库登录，回到本页刷新状态；朗读 10–20 秒，发送评分，查看逐词及音素反馈。
3. 录音后改文本/口音须重录；连续录音 25 秒自动结束；拒绝权限、断网、取消、超时有可理解提示。
4. 普通登录账号接口返回 403，未登录返回 401；密钥不能出现在前端响应/源码中。
5. 历史导出/导入合并；损坏/较新版本不被覆盖；移动端布局与 Safari 音频解码手工检查。
6. 文库：每天打开“今日一篇”随日期变化、同一天不变；逐词高亮在你常用的浏览器和系统语音下是否跟得上；Safari 里点词发音；手机上的排版。
7. 跟读：选一句后录音，文本被锁定；录音中切换页面被拒绝；评分后点“下一句”再读。
8. 听写探针：在 Chrome 和 Safari 各点一次，记下是否能听到、报什么错。
9. 实时亮词：开启后读一段，词是否跟得上、读错是否变红；Chrome 与 Safari 里录音和听写能否同时进行；关掉后完全不调用听写。
10. 朗读整篇：读完一篇 3–4 段，中途“重读这一段”；管理员取消勾选一段后送评，报告里的分数和难词；“练这个词”后单词评分。
11. 背诵：开启实时亮词后背一首诗，三个级别各一遍；故意漏一整行和背错一个词，看扣分是否合理；背诵时练习区看不到原文。
12. 配音：在手机上选一个角色走完一段对话；两个角色的声音是否听得出区别；设备没有范读声音时能否手动继续。
13. 档案：读完一篇、加几个生词、隔天复习；导出再导入一次，确认没有丢东西；在无痕窗口（存储可能被禁用）打开，页面不报错。
14. 评分增强：管理员评一次美式、一次英式，确认韵律分只在美式出现、词的起止时间存在、“听我读的这个词”能播出对应的词。
